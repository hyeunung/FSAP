# T05 해석(해석부) — 테이프 공급·장력 유닛, v0.4.0

**요약(10줄)**
- 대상: 새 하중 부품 6개(`P_T05_PLATE`·`GUIDE`·`HOLDER`·`HUB`·`CAP`·`PAD`) + 임시 형상 축 `STEP대기_PSFJ16-100`. 바뀐 기존 부품 0. 해석 못 함 — 환경 없음(자료대기 D-16), 강도는 손계산(`fea/cases/mech_T05_handcalc.py`). STEP 대조 15건 어긋남 0.
- **동작 문제 1건: `P_T05_PLATE` 혀(Y 560~620, Z 30~100, t3)가 오조작에서 SF 0.80(롤 걸림)·0.81(안내 블록 걸림) < 1.2 → 영구 변형.** 안내 블록이 혀 끝에서 X로 55.8 떨어져 있어 오조작 장력 417.5 N이 판 밖 굽힘 171~246 MPa·비틀림 104 MPa를 만든다(VM 252~257 MPa, SUS304 205).
- 고치는 법: 혀 두께 **t3 → t5**(SF 2.16 / 2.23 ≥ 2) 또는 t6(3.06 / 3.18). 운전(장력 31.9 N)은 t3에서 SF 10.4로 문제없다.
- 디테일 3건: 안내 블록 앞벽 오조작B(외팔 SF 0.99, 두 변 고정 추정 1.98), M5 인서트 조임 토크 2 N·m에서 암나사 전단 0.85(→ 1.5 N·m 이하, 1.13), 허브 고착 시 축이 홀더 클램프에서 돎(40.5 > 9.6 N·m, 미끄럼).
- 합격: 안내 블록 C틀 SF 5.0~17.5, 막대 r8 오조작 SF 2.57, 옆벽 3.80, 인서트 오조작 암나사 3.04, 뿌리 볼트(보수) 5.96, 축 16(오조작)·260(운전), 패드 T홈 14.6.
- 과사양(M-09, 문제로 세지 않음): 축 Ø16 운전 SF 260 → Ø10 후보(선정에서 이미 디테일로 적음).
- 모델 표 `fea/models.json`에 T05 6항목을 더했다(옛 모델 바꿈 없음).
- 미완: 고체 FEA 교차 검증(D-16). 오조작 장력 417.5 N은 매트 미끄럼 힘이고, 테이프 파단 강도(D-06)가 278 N보다 낮으면 t3도 영구 변형 전에 테이프가 끊긴다.

좌표: 대기 자세 세계 좌표(바늘점 원점, 매트 밑면 Z 0), 단위 mm·N·MPa. 패드는 저장값 −12.5.

## 워크플로우 메모

- 해석부 지시의 하중 목록(추력·작업 저항·자중 ×3 g)에 오조작 하중이 없는데, M-09는 오조작 SF 2를 요구한다. 이번에는 `fea/models.json` `P_T02_BINDER`의 "테이프가 걸려 417.5 N"을 그대로 썼다. 테이프·와이어처럼 당겨지는 부품은 "파단 강도 또는 구동 미끄럼 힘 중 작은 값"을 오조작 하중으로 정하는 규칙이 있으면 과제마다 갈리지 않는다.
- 선정 손계산(평판 혀 SF 12.7)은 운전 장력만 봤다. 선정 단계 손계산 표에 오조작 줄을 의무로 넣으면 이번 동작 문제를 구상 단계에서 잡았을 것이다.
- `handcalc.py`는 Windows 기본 코드페이지(cp1252)에서 `--help`·JSON 출력이 UnicodeEncodeError로 멈춘다(`PYTHONIOENCODING=utf-8` 필요). 이번에는 import해서 썼다.
- `handcalc.calc`는 좌면을 암나사 모재(base)로 계산한다. 머리가 다른 부품(여기서는 SUS304 평판)에 앉는 경우 따로 넣어야 해서 케이스에서 두 번 불렀다.
- 기운 원통(막대 r8)은 STEP에서 CYLINDRICAL_SURFACE가 아니라 유리 B-스플라인 면으로 나온다. STEP 대조 도구가 B-스플라인 제어점 bbox도 보면 좋겠다.
