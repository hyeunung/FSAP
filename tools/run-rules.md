# FSAP 실행 규칙 — 모든 부서가 지킨다

엔진 워크플로우(modeling_round·detailing_round)의 모든 부서 지시문 머리에 붙는 이 프로젝트 고정 규칙이다. 지금까지는 인자 `shellNote`에 매번 통째로 넣었다. 실행마다 바뀌는 것(과제, 그 실행만의 기본값)은 여기 두지 않는다.

1. **엔진은 읽기만.** 엔진 폴더(engineRoot)는 읽기만 한다. 그 안의 어떤 파일도 만들거나 쓰거나 고치지 않고, 그 저장소에서 git 명령(add·commit·branch·push)도 하지 않는다(사용자 2026-10-30 "엔진은 절대 건드리는거 아니야"). 회고 담당은 엔진의 improvement-candidates.md를 읽기만 하고, 개선후보 추가·반복 수 갱신은 같은 표 형식으로 `<root>/docs/reports/engine-candidates.md`에 쓴다(같은 문제면 반복 수를 올린다). 엔진 도구를 파이썬으로 돌릴 때는 반드시 `python -B`.

2. **CAD 통로.** 엔진대로 나눈다(L1-engine '부서 지시문', 안내서 '연결').
   - 모델링부(고치고 저장하는 유일한 부서)는 SolidCraft MCP(`mcp__solidcraft__*`)로 그린다. 사용자가 앱 창에서 실시간으로 본다(사용자 2026-10-31 "T06부터 MCP로").
     - 순서: `open {path: tools/config.json doc의 이전 버전 .sc}` → `inspect_design`로 dirty 확인(dirty면 멈추고 보고하고, 버리지 않는다) → `batch`·`execute`로 그림 → 저장 전 대기 포즈(`motion.play` step 0) → `save {path: 새 번호 .sc}`.
     - `save {}`(덮어쓰기)는 쓰지 않는다. 모델링부는 `solidcraft-cli run --save`로 모델링하지 않는다.
     - 예외: MCP 서버 안내의 Backend가 headless이거나 MCP 도구가 없으면 모델링부도 CLI로 하고, 그 사실을 보고서에 적는다.
   - 그 밖의 부서(측정·구상·선정의 CAD 확인·점검·검도·체결·해석 등 읽기만 하는 부서와 동시에 도는 부서)는 MCP를 쓰지 않는다. CLI로 저장본에 대고 잰다.
     - 명령 목록과 인자: `solidcraft-cli commands`(JSON, id·params). 설명: `solidcraft-cli exec engine.describe`.
     - 편집: 명령 스크립트 JSON 배열 `[{"command":"<id>","params":{...}}]`를 만들어 `solidcraft-cli run <script.json> --in <이전 버전.sc> --save <새 버전.sc>`로 새 번호 파일에 저장한다. 실패한 단계가 있으면 아무것도 저장되지 않는다.
     - 읽기·검사: `solidcraft-cli eval <script.json> --in <저장본.sc> --json-out <파일>`. 저장본을 바꾸지 않는다.
       - `--json-out`은 마지막 측정만 담는다. 단계별 결과가 필요하면 `solidcraft-cli run <script.json> --in <저장본.sc> --results`를 `--save` 없이 돌린다.
       - 명령 하나만 부를 때는 `solidcraft-cli exec <명령> <json>`.
     - 그림 확인: `solidcraft-cli snapshot --in <.sc> --out <png> --view iso`. 설계 이력: `solidcraft-cli script <.sc>`.
     - 스크립트·출력 JSON은 `<root>/tools/out/` 아래에 둔다. 안내서의 MCP 명령 이름(motion.interference, joint.sweep, inspect.interference 등)은 같은 id로 CLI 스크립트 안에서 쓴다.

3. **새 번호 저장.** 사용자가 SolidCraft 앱에 연 파일과 이미 있는 버전 파일은 덮어쓰지 않는다. 형상이 바뀌면 항상 `3D_Modeling/FSAP_v<주>.<부>.<수>.sc` 새 번호로 저장하고(요구서 8-2, E-05) `tools/config.json` doc를 바꾼다. 최신 파일은 `tools/config.json` doc가 가리키는 것이다(버전 이력은 CHANGELOG.md). 같은 형상은 `tools/gen_*.py` 생성기로 다시 만들 수 있다. 잠금 파일 `.~*.lock`은 건드리지 않는다.

4. **Git**(요구서 8-5). 새 버전 .sc를 저장했을 때만 FSAP 저장소에서 커밋하고 푸시한다. 브랜치는 `modeling/mat-rs-001`이다(main에 직접 커밋 금지). git 작성자가 설정돼 있지 않으면 `git -c user.name=hyeunung -c user.email=68310338+hyeunung@users.noreply.github.com commit`으로 준다. 버전이 바뀌지 않은 문서 변경은 다음 버전 커밋에 함께 넣는다.

5. **환경.** 셸·파이썬·경로는 이 컴퓨터에 맞춘다. Windows는 Git Bash, `python -B`, 경로는 슬래시, 한글 출력은 `python -X utf8`.

6. **모르는 값.** 모르는 치수는 자료대기(`docs/waiting-list.md`) D-번호의 임시값으로 진행하고, 쓴 임시값과 그 근거를 보고서와 자료대기 '쓰는 곳'에 적는다. 경쟁 기계 사양을 우리 사양처럼 쓰지 않는다. 재봉 헤드는 기종 미정(D-10)이므로 E-10 임시 형상 `STEP대기_<이름>`으로 두고 치수 근거를 적는다. 매트·테이프의 유연한 거동(눌림 복원, 테이프 주름)은 모델로 판정하지 않고 요구서 7절에 기록만 한다.

7. **준비물.** 자료대기 D-번호 임시값으로 만든 준비물은 준비된 것으로 본다(ready=true, done=true, 임시값 목록 첨부). ready=false·done=false는 준비물을 아예 만들 수 없을 때만이다(WF-051).

8. **CLI 함정**(WF-055).
   - `motion.interference`는 기본 시간 예산에서 끊긴다(truncated: true). budget_s를 넉넉히 주고 truncated를 반드시 확인한다.
   - 슬라이더 조인트 방향은 원점의 z로 정해지고, flip을 안 주면 뒤집힌다.
   - `sketch.offset`은 연결 체인을 다 잡지 못하고, 시계 방향 호가 섞이면 붕괴한다. 띄운 윤곽은 직접 계산해 그린다.
   - `timeline.inspect`는 빈 설계에서 못 부른다(`document.inspect`를 쓴다).
   - `motion.study`의 회전 조인트 키는 도(°)다.
   - 상자 두 개를 바깥면이 같은 평면이 되게 join하면 거부된다. 한 스케치를 밀어 한 바디로 만든다.
   - 기계 정의 `tools/machine.json`이 없으면 `tools/motion_states.json`을 같은 역할로 쓴다(WF-086).

9. **matcheck.** `matcheck.py`는 가공품 BOM이 없으면 예외로 멈춘다(WF-056). BOM이 없으면 재질 점검은 '검사 대상 없음(BOM 없음)'으로 기록하고 넘어간다.

10. **구매품 STEP.**
    - 받은 STEP은 `purchased-step/<형번>/<형번>.stp`에 있다(stepcheck로 확인한다).
    - 미스미: 요구서 3-2대로 다운로드와 CAD 약관 동의가 허락돼 있다. 주문·결제는 금지이고, 로그인이 풀리면 재로그인하지 않고 자료대기에 남긴다.
    - 브라우저 도구를 쓸 수 없는 부서는 필요한 형번을 needs_step·자료대기에 남기고 E-10 임시 형상으로 진행한다.
    - **로그인이 풀렸거나 STEP을 못 받으면 기다리지 않는다**(사용자 2026-11-01 "로그인 풀리면 형상치수 보고 대충 그려놓고 진행하기로 했잖아 나중에 다운로드 하고"). 카탈로그 외형 치수(웹 규격표·외형도)를 보고 `STEP대기_<형번>` 임시 형상을 바로 그리고 과제를 계속한다. 같은 과제 안에서 받기를 다시 시도하거나 멈추지 않는다. 실물 교체는 다음 라운드의 STEP 재시도가 한다.

11. **STEP 받기 범위**(사용자 2026-10-31 "부품 적용할 수 있을 때 틈틈이 다 해줘", "빼먹지 말고 STEP 파일로 다 바꾸고 넘어가자").
    - 받을 것: 구매부는 이번 과제 형번뿐 아니라 형재 마감캡(C-11, U-19)과 자료대기에 STEP 대기로 남은 형번도, 받을 수 있으면 받아 `purchased-step/<형번>/`에 둔다.
    - 형번 표기: 미스미 형번 표기가 다르면(신형 접미사 등) 같은 사양의 미스미 표기를 찾아 자료대기에 적는다.
    - 넣는 법: 새로 넣는 구매품은 처음부터 받은 실물 STEP으로 넣고, 새 형재에는 처음부터 마감캡을 단다.
    - 브라우저: 새 탭을 만들어 쓰고, 사용자의 기존 탭은 건드리지 않는다.
    - 제조사 CAD 사이트: 미스미에 CAD가 없거나 제조사 CAD 사이트로 넘어가면 그 사이트(SMC CAD, 오리엔탈모터, CADENAS PARTcommunity, TraceParts 등)를 써도 되고, 그 사이트의 CAD 약관 동의도 된다(사용자 2026-10-31 "SMC 말고 다른 사이트가 나오더라도 다 써도 되니까 받아서 진행해").
    - 금지: 회원가입·로그인·비밀번호·개인정보 입력·주문은 하지 않는다. 필요하면 멈추고 자료대기에 남긴다.

12. **미스미 로그인 확인**(사용자 2026-10-31 "플로우 마지막에 항상 로그인되어 있나 확인해줘").
    - 구매부: 받기 전에 미스미 화면 머리에 '로그인 / 회원가입'이 떠 있는지 먼저 본다. 풀려 있으면 받지 않고 결과에 `login: false`를 적는다.
    - 최종 보고 담당: 마지막에 Chrome 새 탭으로 미스미를 열어 로그인 상태를 확인한다. 최종 보고 맨 위에 '미스미 로그인: 됨/풀림'과 이번 실행에서 로그인 문제로 못 받은 형번 목록을 적는다.
    - 재로그인·비밀번호 입력은 하지 않는다.

13. **완료 기준**(사용자 2026-11-01 "구동부 끝이라는게 완전히 완료되는거 말하는거야 제품으로 나가도되겠다").
    - '완료'는 제품으로 출시해도 될 상태다. 요구서 과제가 '해결'인 것과 다르다.
    - 아래 다섯 가지가 모두 0이어야 완료다.
      - 열린 구동 과제
      - 구동 후보
      - 동작 문제
      - 디테일
      - 형번이 정해졌는데 `STEP대기_`로 남은 구매품
    - 사용자 자료로만 풀리는 것(재봉 헤드 D-10, 납품처 안전 기준 D-38, 사이트 로그인)만 남았으면 '사용자 자료 대기'로 보고한다.
    - **순서**(사용자 2026-11-01 "구동부 하나 하고 디테일링하고 또 구동부 하나 하고 디테일링하고 이것도 하지 말라고 했잖아. 구동부 다 완료가 되고 나면 디테일링을 하라니까"): 구동부를 먼저 100% 끝낸다. 구동 과제와 구동 후보가 0이 될 때까지 구동 라운드만 거듭한다. 그다음에 디테일링을 한 번 한다. 구동과 디테일링을 번갈아 돌지 않는다.
    - 구동 라운드는 디테일링이 낼 만한 구동 후보도 미리 찾는다. 높이 사슬, 볼트 렌치 접근을 막는 배치, 구매품 수량·외형처럼 배치를 바꿔야 풀리는 것은 구동 단계에서 끝낸다.

14. **커버·외장은 구동이 아니다**(사용자 2026-11-01 "이거 룸은 왜 구현한거야? 기구물 동작이랑 아무상관없는거잖아").
    - 옆·뒤 커버, 가드 판넬, 외장 판금, 정비 문은 구동 과제·구동 후보로 만들지 않는다. 과제 정리부는 요구서 5절에서 종류가 '구동 아님(외장·안전)'인 행을 넣지 않는다.
    - 그런 것이 필요해 보이면 결정로그 '외장 단계 과제' 표에 적기만 한다. 납품처 안전 기준(D-38)이 정해진 뒤 사용자가 시킬 때 한다.
    - 구동 과제는 기구가 움직이고 작업 대상(매트·테이프)을 다루는 데 필요한 것뿐이다: 구동 유닛, 그 받침·안내, 배관·배선 길, 공구 접근, 높이 사슬, 구매품 실물 교체.
