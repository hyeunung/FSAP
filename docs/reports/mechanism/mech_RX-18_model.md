## 워크플로우 메모

- CLI 4개 병렬 + 앱(메모리 30~33 GB)에서 `solidcraft-cli run` 하나가 88 s에 exit 139로 죽었다(출력 0바이트). 혼자 다시 돌리면 통과한다. 병렬 묶음 실행기는 exit 코드가 0이 아니거나 결과가 비면 한 번 혼자 다시 돌리게 하면 된다.
- 이번 저장본에서 CLI 한 번(열기 + 연구 하나 5묶음 전 구간)은 244~322 s, 저장 확인은 189 s였다. 앱의 `motion.play`는 0.3~0.6 s(한 번 45 s — `J_U6_PRESS`가 바뀌는 단계), `inspect.clearance`(40바디 ↔ 54바디)는 0.2~0.5 s라 자세별 bbox 확인은 앱이 빠르다.
- `motion.interference`는 쌍이 많으면 부피를 내지 않는다(`not_measured`: 256 교차 한도). 통과 기준이 겹침 bbox(X 최소)라서 자세별 `inspect.clearance`를 따로 돌려야 했다 — 설계 지시서의 통과 기준이 bbox면 검사 명령도 같이 적어 주면 된다.
- 설계 단계의 평면 계산 구간(P2 240~359)과 CAD 전 단계 결과(242~359)가 2단계 달랐다. 기준선 문구에 단계 범위를 넣을 때는 모델링 뒤 값으로 확정하는 칸을 두면 된다.
- `mcp_send.py`를 `>` 로 돌리면 파이썬 출력이 버퍼에 남아 진행 로그가 비어 보인다(결과 JSON으로 진행을 봤다).
- 엔진 규칙 원문(L1~L3) · 요구서 · 자료대기는 이번 회차에 통째로 읽지 않고 지시문에 실린 조항과 설계 보고서의 인용을 썼다.
