## 워크플로우 메모
- `component.delete`는 큰 설계에서 1번에 3분 넘게 걸리고, 관 바디(루트 피처로 만든 뒤 옮긴 것)는 지우지 못한다. 관 바꾸기는 `solid.remove` + 옛 컴포넌트 `component.rename`이 0.6 s로 훨씬 빠르다.
- `occurrence.move`는 리지드 그룹에 묶인 occurrence를 거부한다. 리지드 그룹은 `Rigid Group a:b` 짝 조인트 여럿이라 `joint.list`에서 그 occurrence id 짝만 지우고 옮긴 뒤 다시 묶으면 된다.
- MCP batch 응답이 스케치 단계마다 커서(관 200단계 ≈ 60 KB) 대화 토큰을 많이 먹는다. 배관처럼 단계가 많은 과제는 관 하나를 명령 하나로 만드는 길(예: 점·반지름 목록을 받는 3D 관 명령)이 있으면 좋겠다.
- 배관 과제 L 등급(관 26줄 + 고정품 35 + 볼트 62 + 체인 행정 모형)은 모델링 한 회차 180분에 다 들어가지 않는다. 과제 정리 때 '관·이음'과 '고정품·체인'을 나누는 편이 맞다.
