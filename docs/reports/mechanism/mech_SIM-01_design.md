## 2. 그네(M02R)가 테이프에 주는 영향 — 손계산

1. 바퀴 밑 높이: M02R 연구 키 환산(`keymap.json`)은 옛 키 → 같은 바퀴 밑 높이 → 새 키다(8.626 → 13.006, 0 → 0, −0.54 → −0.960, 2.4289 → 3.751, −1.867 → −3.349, 0.306 → 0.477). 그래서 단계마다 바퀴 밑 Z는 v2.10.0과 같다.
2. 키 반올림: 피벗–바퀴 중심 138.92, 수평 팔 120 → dz/dθ = 120 × π/180 = 2.09 mm/°. 키 소수 셋째 자리(0.0005°) → 0.0011 mm, 0.001° → 0.0021 mm. 가장 좁은 틈 0.0356 mm > 0.0021 → 틈 0.033 이상 남는다.
3. 접지 Y 이동: 두께 6 +1.19, 16 −4.32 mm. 붙은 테이프 윗면은 매트 윗면 위 평면(Z 11, L 매트)이라, 원통 바퀴 가장 낮은 줄이 Y로 옮겨도 수직 틈 = 바퀴 밑 Z − 11 은 같다. 테이프 끝선(Y 2.0) 밖으로 나가면 틈은 늘기만 한다.
4. 바퀴 면 기울기: 새 피벗 축 X ∥ 바퀴 축 → 0°(옛 Y축 피벗은 들림 때 8.6°). 봉제 자세에서 바퀴 가장자리가 내려앉아 테이프를 긁는 일이 없다(옛보다 나쁘지 않음).
5. 대기 조각: Z 2000~2011. 새 U4 최고 Z 250(브래킷), 기계 최고 915.5 → 틈 1,084.5.
6. 테이프 줄 ↔ 새 U4: 줄 X ≥ −11(TL_FEED X −2.5, TL_LOW 슬롯 X 13.5~44.5), 새 U4 부품 X ≤ −180 → X 틈 ≥ 169(그네 끝 −180 − (−11)). 실린더·브래킷은 X ≤ −215, Y 177.93~262로 테이프 슬롯(Y −111~−109)과 Y로 287 떨어짐.
7. P_M02_DISK(바퀴 밑 회전 원판)는 M02R이 바꾸지 않음 → TAPE_L 밑면 Z 0 맞닿음(거리 0, 겹침 0) 그대로.

결론: 그네로 바뀌어도 테이프 줄·붙은 조각 간섭 판정은 v2.10.0과 같아야 한다. 검도는 이것을 새 저장본에서 수치로 확인한다.

## 5. 검도 지시(모델링 지시서 대신 — 형상 변경 없음)

1. 대상: M02R 모델링이 저장한 새 번호 .sc(`tools/config.json` doc). 그 전에는 돌리지 않는다.
2. 이름 확인: 저장본에서 `component.list`(또는 `document.inspect`)로 WP_TP_* 경로를 확인한다. v2.10.0은 루트(`WP_TP_L_01:1`), v2.10.1 check2는 `WP_TAPE_L:1/WP_TP_L_01:1`로 썼다 — 저장본에 있는 쪽으로. L은 16B·26B 포함 43개 + SEAM.
3. against(5연구 같음): `U3_PRESSER:1, U3_NEEDLE:1, U4_PRESS:1, U4_WHEEL:1, U4_DISK:1, U4S_CYL:1, U4S_ROD:1, U5_CAR:1, U5_LIFT:1, U5_WHEEL:1, U5_FLOAT:1, U6_SHOE:1, U6_PRESS:1, U6_SENSOR:1`. `U4_CYL`·`U4_ROD`는 지움. 저장본에 `U4S_SLOT`·스프링 컴포넌트가 따로 있으면 더한다.
4. 스크립트: `tools/out/mech_SIM-01/check3/chk_<연구>.json` = [browser.visibility {folder:"all", visible:true}, motion.interference {study, occurrences, against, budget_s 470}, motion.interference {study, occurrences [U7_TAPE_LINE:1, U7_TAPE_FEED:1], against [WP_MAT_<M>:1], budget_s 300}]. `check2/run.sh`를 check3으로 복사해 `run.sh <새.sc> <연구>` 5개를 백그라운드 병렬(CLI, regrun 상한 30분, 요구서 6-4).
5. 합격: 첫 검사 overlaps 0, 둘째는 TL_FEED↔매트 ≤ 225 mm³(기준선), 둘 다 truncated false, 표본 수 v2.10.0과 같음(717·451·515·631·487). 커널 패닉·0바이트면 그 연구만 다시.
6. 바퀴↔테이프 틈 확인(MCP 짧은 확인 또는 CLI): CYCLE_L 172단계에서 `inspect.clearance` U4_WHEEL ↔ WP_TP_L_*(근처 조각) ≥ 0.03 mm. 겹치면 keymap 값(소수 셋째 자리)을 고치고 기준선으로 넘기지 않는다.
7. 영상: `anim/anim_CYCLE_*.json`을 새 .sc로 다시 돌려 `anim3/`(GIF + 바늘 PNG, 연구당 167프레임 안팎, stopped null). U4 그네가 보이는 카메라는 anim2의 needle_A 그대로.
8. 끝나면 `motion.play` REST step 0. 저장 금지.

## 0. 출발점·규칙

- basis: 0-8-3 U7 "그대로 가져오는 벤치마크: R375X(테이프 커팅 유닛·열절단 옵션, 헤드 위 실린더), 867 바인더, US6044783A, US4688499". 테이프 길(롤 → 안내 → 바인더)은 이미 M06·FUNC-01·REG02에서 벤치마크대로 놓였고, 이 과제는 **그 길을 실제 두께·폭 테이프 바디로 잇고 봉제 진행을 동작 연구로 보이는 것**이다. 새 구동·새 배치 없음(E-01 "구동 개념이 확립됐으므로 … 상세 설계하는 단계").
- 0-8-2 ④ "테이프 길(롤 → 바인더)은 윗헤드 높이로 지나가 매트와 만나지 않는다" — TL_UP·TL_TWIST·TL_LOW는 Z ≥ 41.5(매트 Z ≤ 11), 만나는 것은 바인더 출구 뒤 TL_FEED(바늘 앞 7.5 mm)뿐.
- E-02 "구동부 → 브래킷 → 디테일": 이 과제는 강도·볼트를 다루지 않는다(새 볼트 0). 필렛은 기능(테이프 굽힘 기준) 때문.
- E-15 "움직임은 기계 정의의 조인트로만": 단계별 붙은 테이프도 조인트(J_TP_*)로 만든다. 바디 표시 키는 없다(`motion.study` keys: [{joint, …}]).
- E-19 "같은 것은 묶어 가장 불리한 하나만": 테이프 줄은 프레임 고정이라 움직이는 이웃이 가장 가까운 자세(J_U6_SHIFT 0)가 가장 불리.

## 1. 구동 방식·순서

테이프 줄에는 구동이 없다. 롤은 헤드 끌힘(3중 이송, 30 N D-79)으로 풀리고, 이송 집게(J_U7_FEED)·절단(J_U7_CUT)·끝 접기(J_U7_TUCK)는 연구 CYCLE_*에서 대기값 0(REG-01) — 테이프 줄은 사이클 내내 프레임에 고정이다. J_U7_HGT −4~+6은 매트 사이에만 바꾸므로 사이클 안에서 0.

| 단계 | 테이프 줄 | 붙은 테이프 조각 |
|---|---|---|
| 0(시작 전, 매트 대기 자리) | 고정 | 그 연구 매트의 조각 모두 Z +2000(대기), SEAM도 +2000 |
| 봉제 진행(땀 위치 s) | 고정 | 조각 끝 호 길이 s_end ≤ s 가 된 단계에서 2000 → 0(한 단계 안에서) |
| 이음 겹쳐 박기 끝 | 고정 | SEAM_* 2000 → 0 |
| 끝(꺼냄) | 고정 | 모두 0(가공 뒤 형상 = 지금 TAPE_* 와 같음) |

REST 연구는 모든 J_TP_* 0(지금 TAPE_* 상태 그대로, 숨김) — 대기 포즈가 지금과 같다.
