## 3. 구동 방식·순서·자세

- 구동: 모형용 조인트 3개(`J_WP_P_X` 슬라이드 → `J_WP_P_Y` 슬라이드 → `J_WP_P_ROT` 회전, 원점 PARK, 한계 ±3000 mm · −360~720°, `model_only`). 매트 중심 c = −R(ROT)·p(p = 바늘 밑 땀 점, 매트 좌표), X = c_x + 253.5, Y = c_y + 300, ROT = −90° − (땀 진행 방향 각). 시계 방향: ROT 0 → 90 → 180 → 270 → 359.09 → (홈 바닥에서 되돌아) 180 → 180.91 → 270 → 360.
- 단계 간격(요구서 6-4): 몸통 직선 25 mm, 띠·홈 구간 전부와 그 앞뒤 50 mm는 5 mm, 회전·둥근 모서리·홈 바닥은 1°.
- 키 약속은 `CYCLE_W`·`CYCLE_G1`과 같다: 노루발 20 → 0 뒤 끝까지 0(C-39), 각진 모서리 회전과 홈 바닥은 바늘 −30 · `J_U6_PRESS` 4.5, 봉제는 0 · −0.4, `J_U6_SHIFT` 0, `J_U5_X` 1360(d₂ 440, D-152), `J_U5_LIFT`·`FLOAT` 내림 −10·10 / 들림 30·0, `J_U4_PRESS` 내림 0 / 들림 13.006, `J_U7_*` 0, 다른 매트 `J_WP_L·S·G·V·W_*` 0. `J_U4_X`는 키 없음(d₁ 100 — 지금 범위 0~95로는 d₁ 45를 못 만든다, RX-16 뒤 다시).

요구서 7절에 더할 기록: ① 띠(폭 60)가 홈 뿌리로만 이어져 있을 때 건너편 몸통을 누른 바퀴가 띠를 같이 잡아 주는지(강체 모형에서는 접지로 나옴) ② 두 바퀴 없이 노루발·바늘만으로 띠의 홈 쪽 벽 151 mm를 박을 때 띠의 흐름·비틀림(d₁ 45 뒤에도 접지 0.80~1.00) ③ 포켓 위로 나간 건너편 몸통의 처짐 ④ 띠 끝 각진 두 모서리에서 테이프 감김.

## 미완

- 새 매트의 CAD 전 구간 간섭(`motion.interference`)은 모형이 생긴 뒤 검도가 한다. 이 보고서의 전 구간 값은 평면 강체 계산이다.
- 설계검토서·요구서 0-8-5(시험 매트 줄)·7절·5절·자료대기 '쓰는 곳' 반영은 문서 담당.
- d₁ 45 연구는 RX-16 뒤.
- 해석: 대상 없음(기계 부품 0). 참고로 이 컴퓨터는 '해석 못 함 — 환경 없음(자료대기 D-16)'.

## 워크플로우 메모

- `joint.drive` 8개를 한 `batch`로 보냈더니 약 7분 돌았고(MCP 호출은 시간 초과로 돌아옴), 그동안 세션의 MCP 서버가 "Server unavailable"이 됐다(다시 붙으려는 `mcp.options`가 내 요청 뒤에 줄을 섬). 같은 MCP 서버(`solidcraft-cli mcp`)를 스크립트로 띄워 `running`으로 기다린 뒤 이어 쟀다(`tools/out/mech_RX-17/design/mcpcall.py`). 큰 파일에서 조인트 구동은 하나씩 보내는 것이 맞다 — 안내서 '연결'에 조인트 구동 한 번의 시간(이 파일 약 50 s)을 적어 두면 좋다. 측정부 메모(첫 batch 시간 초과)와 같은 원인이다.
- `edit.restore_checkpoint` 56.6 s.
- 작업 대상 모형만 더하는 과제에도 구매품·볼트·렌치 접근·하중 손계산 지시가 그대로 붙는다(대상 0) — RX-12 메모와 같다(반복).
- 과제 이름은 `CYCLE_P` 하나인데 단계가 1,088이라 표본 상한(1,000) 때문에 둘로 나눴다. 과제 정리부가 "CYCLE_P(상한을 넘으면 P1·P2)"로 쓰면 다시 판단하지 않아도 된다.
- `tools/machine.json`의 `doc`가 v2.17.2로 남아 있다(측정부와 같은 지적).
