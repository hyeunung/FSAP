## 워크플로우 메모

1. 모델링 미완이 "검사를 못 끝냄"뿐일 때도 수정 회차 지시문은 "먼저 다른 이름으로 저장해 마지막 자리 +1 새 파일"을 시킨다. 검사 결과 고칠 것이 없으면 형상이 같은 빈 번호가 생기고(E-05 WF-027 "빈 번호를 남기지 않는다"와 어긋남), 새 파일을 안 만들면 번호 점검이 "덮어씀"으로 적는다. 형상을 안 바꾼 수정 회차는 `version_bump: none` · 같은 문서를 허용하는 편이 맞다.
2. 수정 회차의 모델링 결과가 앞 회차 결과를 통째로 대신하므로(검도·해석·문서가 이 결과의 `changed_parts` · `exported_steps` · `report_path`를 받음), 검사만 한 회차도 과제 전체의 바뀐 부품·임시 STEP을 다시 내야 한다. 이번에는 그렇게 냈다.
3. `joint.drive J_U4_X`는 저장본 CLI에서도 한 번 465~574 s다(앱 10~13분). 과제 범위 검사의 X 점마다 CLI 하나씩 병렬로 띄우는 것이 가장 빨랐다(열기 약 15분 + 구동 약 10분, 점 수와 무관하게 약 26분). 지난 회차 메모 1(이력 끝 917피처가 구동마다 다시 계산됨)과 같은 원인이다.
