## 2. 지난 문제 확인

| 지난 문제 | 이번 | 근거 |
|---|---|---|
| 동작: 평판 혀 오조작 SF 0.80 / 0.81(t3) | **해결** | 저장본 `P_T05_PLATE` bbox X −80.0~−75.0, Y 560~850, Z 30~245, SUS304(`bp_out.json` measure). 손계산(`tools/out/mech_T05/model1/hc_r1.json`): 오조작A σ판밖 61.6, τ비틀림 38.3, VM 95.1 MPa, SF 2.16 / 오조작B σ판밖 88.6, VM 92.1, SF 2.23 / 운전 SF 28.36 |

손계산을 다시 따라 계산했다(오조작A): σ = 17,955 / (70·5²/6) = 61.6 MPa, β = (1/3)(1 − 0.63·5/70) = 0.318, τ = 21,328 / (0.318·70·5²) = 38.3 MPa, VM = √(65.1² + 3·40.1²) = 95.2 MPa → SF 2.15. 모델링부 스크립트의 단면 기준점은 옛 판 중앙 X −76.5인데 새 중앙은 −77.5다. 하중점(X −132.3)까지 팔이 1 짧아져 모멘트가 줄므로 −76.5 쪽이 보수적이다. 해석부 2회차(`mech_T05_fea1.md`)는 2.19 / 2.26이다. 같은 판정이다.

## 워크플로우 메모

- `ledger.py`·`matcheck.py`를 Windows 기본 코드페이지(cp1252)에서 돌리면 한글 출력에서 UnicodeEncodeError로 멈춘다. `PYTHONIOENCODING=utf-8`을 주면 돈다. 엔진 도구 실행 머리말에 넣거나 도구에서 stdout을 utf-8로 바꾸는 것이 좋겠다.
- 모델링부 손계산 사본(`hc_r1.py`)의 STEP 대조 `chk`가 옛 기대값 −78을 그대로 써서 `ok false` 3건을 낸다(실제 값 −80이 맞다). 수정 회차에서 스크립트를 복사하면 대조 기대값도 함께 바꾸도록 안내하면 좋겠다.
