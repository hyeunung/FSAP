### 워크플로우 메모

1. `joint.drive`는 한계 밖 값을 한계에 묶는다(held). 행정을 늘리는 과제의 측정부는 늘릴 쪽 자세를 CAD로 만들 수 없다 — 한계 자세의 틈(clearance = 늘릴 양 + 1) + 가까운 두 점 방향으로 읽는 방법을 썼다.
2. MCP `batch {path}`는 MCP 서버 임시 폴더(`…/Temp/solidcraft-mcp-<pid>`)와 recovery 폴더만 읽는다. `--allow-path` 작업 폴더의 `tools/out/` 파일은 거부됐다(이 세션 서버는 `--allow-path` 없이 떠 있었다).
3. `inspect.clearance` 한 단계 묶음(near 292쌍)에서 MCP 호출이 시간 초과되고 서버가 없어졌다. 같은 검사가 CLI로는 3.4 s. `inspect_design` · `motion.play`는 인자를 다 꺼도 응답이 134 KB · 1.1 MB라 파일로 떨어진다.
4. v2.20.2(62 MB)의 CLI 한 번(열기 + 구동 4 + 틈 검사 2~3)은 138~141 s였다 — 실행 메모의 "저장본 CLI 열기 13~27분"보다 훨씬 짧다(0.45.0).
5. 같은 과제 폴더에 카탈로그 부서가 동시에 `catalog.md`를 썼다(CAD는 안 씀).
