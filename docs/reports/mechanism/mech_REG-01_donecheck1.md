- 맞음: X1 키 고침(CYCLE_G1 J_U5_LIFT 319~320 = 1.0) — probe 호출 257 s(22:08:59→22:13:16), 10단계 truncated false 10/10, 깊이 0.42 대비 1.0 mm(2.4배). 본/못 본 범위 표 기록됨.
- 안 맞음 1: 못 본 범위 1,655단계를 보지 않고 REG-01-X2로 다시 올렸다. 과제 범위를 이름만 바꾼 것이지 "문제"(찾은 겹침)를 후보로 올린 것이 아니다.
- 안 맞음 2: "묶음당 호출 8분 이내" — 본 범위 932단계 호출은 9~10분(열기 300~420 s + 측정, late 수확), MAINT_U7 호출은 37분 넘어 죽임(측정 보고서 133행). X1 probe 하나(257 s)로 met 처리했다.
- 미완: v2.5.8은 아직 없다(3D_Modeling 최신 v2.5.7, config doc v2.5.7). 회귀 계획은 계획일 뿐 결과가 없다.

## 2. 고칠 자리
1. 모델링부가 X1 키(`[318,0],[319,1.0],[320,1.0],[321,30]`)를 넣고 앱(MCP) `save {path:"3D_Modeling/FSAP_v2.5.8.sc"}` → `solidcraft-cli bench-open`으로 `adopted` 확인(열기 254 s → 수 초가 목표). design.md 4절 단계 5~6.
2. v2.5.8에 대고 못 본 범위 1,655단계를 regrun으로 실제로 본다(호출 ≤ 480 s, truncated 0). 캐시가 안 들면(B안) 묶음을 연구 80~120단계·자세 25~40점보다 작게 잡아 열기 254 s + 측정 ≤ 480 s(측정 여유 약 220 s)로 맞춘다. MAINT_U7 CST_Y 250 단계는 따로 `motion.interference`(budget_s 400) 하나로.
3. 본 범위 중 9~10분 걸린 호출 결과(late)는 v2.5.8 회귀에서 같은 묶음 크기로 다시 돌려 8분 안 결과로 바꾸거나, 이 항목을 v2.5.8 회귀 결과로 판정한다.
4. 1,655단계에서 겹침이 나오면 그 겹침마다 구동 후보로 등록한다(그때가 "문제를 구동 후보로 등록"). REG-01-X2 행은 그 결과로 닫는다.

## 워크플로우 메모
- 설계 부서(CAD 저장 금지)에게 "못 본 범위 전부 간섭 0"을 완료 판정으로 주면 수정 회차가 '범위 재등록'으로 흐른다. 회귀 과제의 완료 판정은 모델링·회귀 뒤 단계에서 보게 나누는 것이 맞다(설계안 메모와 같은 의견).
