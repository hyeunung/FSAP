## 5. 회귀 담당에 넘길 것
1. `chunk7.py` 연구 단계 앞 0으로 모는 조인트에 `J_U6_SHIFT`를 더한다(지금 `('J_U6_HGT','J_U7_HGT')`). 자세 세션과 나눠 돌면 지금도 넘어옴은 없지만 지시대로 맞춘다.
2. 연구 명세 순서: CYCLE_S 363~450 → CYCLE_G1 → CYCLE_G2(위 12단계 빼도 됨). 상한 30분에 약 300단계라 다음 회귀는 CYCLE_S 363~450 + CYCLE_G1 0~약 215까지 본다.
3. 자세가 느린 이유는 검사(18~21 s)가 아니라 자세 잡기(REST에서 J_U5_X 0 → 1380 큰 이동의 접촉 계산, mech_regression2.md: joint.drive 264.6 s, POSE_TMP 134.6 s)다. chunk7 POSE는 점마다 `motion.play REST` 뒤 몰아서 매번 큰 이동이 된다. 같은 묶음 안에서 J_U5_X 순서대로 25 mm씩 이어 몰면(REST로 돌아가지 않고) 자세 잡기가 크게 줄 것으로 본다 — 회귀 도구 변경이라 회귀 담당이 정한다. 그때 손 조정 조인트 오염이 없게 자세 세션만 쓴다.
4. 기준선 밖 겹침 판정은 machine.json `baseline_overlaps`. 못 잰 쌍(나사·핀 물림 I-020B↔CDM2C20-25Z_ROD·_NUT, KDM10P-06↔KDM10S-06)은 기존 것.

## 6. 기각·주의(같은 실수 막기)
- 전체 회귀를 MCP 앱에서 돌리지 않는다(실행 규칙 2, T14 42분 멈춤). CLI 헤드리스 세션만.
- 자세 세션과 연구 세션을 섞지 않는다(WF-183).
- regrun 어림이 상한을 넘으면 시작 전 앞 묶음만 돌리고 나머지는 못 본 범위로(E-17).

## 워크플로우 메모
- 검증 과제(REG)에 측정부가 끼면 할 일이 범위 정리뿐이다. 남은 범위·중복 정리는 회귀 담당이 regrun 명세 만들 때 같이 해도 된다.
- 자세 점 점마다 REST로 되돌리는 방식이 전체 회귀 시간의 대부분을 쓴다(자세 202점 ≈ 9.7시간 vs 연구 1,222단계 ≈ 2시간).
