## 워크플로우 메모
- 세션 수와 메모리: 앱이 열려 있으면(이번 37 GB, 커밋 61.5 GB) 헤드리스 세션 하나(커밋 약 11.8 GB)도 커밋 한도에 닿는다. 회귀 23은 앱 20 GB에서 2개를 열었다.
  - 안내서 '연결' 나눔 수에 "세션 수 = (커밋 여유 − 여유분) / 세션 커밋" 칸이 없다.
  - 앱 메모리가 클 때 회귀 부서가 할 것(앱을 다시 켜도 되는지)도 정해져 있지 않다.
  - 지시문은 막힘일 때 '앱만 다시 켠다'고 하지만, 메모리 경우는 적혀 있지 않다. 그래서 이번에는 앱을 건드리지 않았다.
- 대기 포즈 되돌리기: `motion.play REST 0`은 연구 키가 없는 조인트를 되돌리지 않는다. 그래서 저장본이 셋업 자세(J_U7_HGT 6)로 남았다. 회귀 23의 '세션 상태 넘어옴'과 같은 뿌리다.
  - 안내서 '동작 상태 초기화'를 "REST 0 + machine.json joints rest 값으로 비연구 조인트 drive"로 고정하면 저장본과 회귀가 함께 풀린다.
- Git Bash `nohup … &`로 띄운 감독의 자식(worker)이 시작되지 않았다. 원인은 heredoc이 `\n`을 풀어 worker.py가 문법 오류였기 때문이고, stderr를 버려서 늦게 알았다. 감독이 자식 종료 코드와 err를 sup_log에 적게 하면 좋다.
