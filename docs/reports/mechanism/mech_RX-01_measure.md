## 워크플로우 메모

- 프로브 상자 14개 + `inspect.clearance` 한 `batch`가 약 500 s 걸려 MCP 응답 한도(약 300 s)에서 연결이 끊기고 결과가 사라졌다. 다시 잰 `inspect.clearance`도 443 s(128쌍 중 125쌍은 재사용, boolean이 실패하는 3쌍이 시간을 다 씀 — 실패한 쌍은 캐시되지 않음). 근거: `running` id 16601 running_s 338 → 496, 두 번째 호출 ms 443,425. 바꾸면 좋을 것: 안내서 '간섭'에 "프로브 `inspect.clearance`는 상자 5개 이하·관(스윕) 바디는 따로 한 묶음"을 적거나, 끊긴 요청의 결과를 다시 읽는 방법(`pending`은 끊긴 연결의 요청을 못 봄).
- `document.inspect`가 1.3 MB라 시작·끝 dirty 확인마다 파일로 받아 파싱한다(RX-06R·RX-10 메모와 같은 것, 반복).
- 과제 문구의 "TU0805 … 지금 모델 기준 R30"은 모델과 다르다(TU0805는 R 40, R 30은 TU0604). 과제 정리부가 완료 판정 문구에 수치를 넣을 때 서명·앞 보고서 값을 인용하게 하면 좋다.
