# RGSEE 설계안: SolidCraft 0.50.0에서 깨져 열리는 v2.30.5 복구 — 2026-11-28 (엔진 v4.1.2)

요약
- **설계안 1개: 형상을 바꾸지 않는 0.50.0 복구.** 새 부품·구매품·볼트·조인트 0. 고치는 것은 이력 피처 149개(스케치 1 · 옮기기 `from` 132 · 옮기기 지움 3 · 둥글림 다시 집기 1, 나머지 오류 4개는 따라 풀림)다.
- **읽기 세션에서 끝까지 해 봤다(저장 안 함).** v2.30.5 임시 사본을 0.50.0 헤드리스로 열어 아래 편집 152명령을 그대로 넣었다: 타임라인 **오류 140 → 0**, 바디 3,758 → **3,759**, 걸린 시간 435 s.
- 복구 뒤 3,759바디를 저장 때 측정(2026-11-27 reg32, 같은 파일)과 대조: **3,755바디가 0.001 mm · 0.001 % 안에서 같다.** 다른 것은 4개 — 다시 그린 관 `TU0604_M08P_U5_B`(+0.40 mm³, +0.0005 %)와 감속기 어댑터 3개(−1.47 %, STEP 불러오기 차이라 받아들임).
- 테이프 조각 139개 + 이음매 4개가 조각 조인트 124개를 모두 따른다(+100 몰면 +100.000). 조인트 658 · floating 0 · conflicts 0 · 컴포넌트 800 그대로.
- 원인 3가지를 찾았다: ① 0.50.0은 나눈 조각(split)을 원래 바디의 컴포넌트에 둔다(앞 버전은 나누기 피처의 컴포넌트) ② 관 경로의 0.75 mm짜리 호 2개(R 13.696, 원래 뜻은 R 30) ③ 둥글림이 이름 대신 형상으로 다른 모서리를 잡음.
- 못 잰 쌍 `P_M04_PANEL_E2 ↔ P_RX15_PIN`은 복구 뒤에도 불리언이 실패한다. 핀 Z −8.0~−6.0, 패널 Z −12.0~−8.0이라 평면 Z −8에서 갈린다(겹침 0, 선 맞닿음) — 상자 값으로 판정한다.
- 편집 기록: `tools/out/mech_RGSEE/design/fix050_edit.json`(단계 묶음 `fix050_stage_1~5`), 생성기 `fix050_gen.py`.

## 워크플로우 메모
1. RGSEE 과제의 기구설계부 예상 15분(등급 S)은 '모형이 깨져 열린다'는 측정 결과와 맞지 않는다. 앱 버전 복구는 원인 찾기 + 실제 파일 시험이 일이라 열기 한 번(700 s)만으로 예상을 넘는다. 측정부가 '앱 버전으로 깨짐'을 내면 과제를 FIX-류로 바꿔 등급을 다시 매기는 길이 있으면 좋다.
2. 준비 점검 · `ledger.py sigcheck`가 앱 버전을 보지 않는다(측정부 메모와 같은 문제, 되풀이).
3. 앞 버전 앱이 '나눈 조각을 켜져 있던 컴포넌트에 둔다'는 것을 아무 검사도 잡지 못했다. 솔 실 4바디가 RX-05 V1(나누기 `RX05V1_SPLIT_B1 · B2`) 뒤로 root에 있었는데 지금까지 어느 보고서에도 나오지 않았다. 유닛 컴포넌트 밖 root에 놓인 바디를 세는 점검이 있으면 잡힌다.
4. 서명 표의 U4 바퀴 · 누름 묶음 29바디 bbox가 REST 측정과 1.4~10.2 mm 다르다(부피 차 0.03 % 안). `sigpatch`가 바뀐 바디만 고치므로 대기 자세가 바뀐 과제(RX-19) 뒤 같이 움직이는 바디의 bbox가 묵는다.
5. 마커를 내린 상태의 `timeline.edit`도 개당 1.27 s다(피처 4,537개 문서). 132개 묶음은 60 s 응답 한도를 넘는다 — 묶음 크기를 40개 안팎으로 잡으면 호출마다 응답을 받는다.
6. `edit.restore_checkpoint`는 `checkpoint` id를 꼭 줘야 한다(안내서 '원복'에는 id 없이 적혀 있다).
7. 실행 도중 앱이 자동 업데이트되는 일을 막으려면 실행 중 자동 업데이트를 끄는 것이 가장 싸다(사용자 결정).
