## 워크플로우 메모

- 앱에서 `joint.drive J_U4_PRESS`가 0 → 13.006(들림)은 0.2 s인데, 13.006 → 3.751 → 0, 0 → −0.96, 3.751 → −4.11은 한 번에 5~8분 걸렸다(motion_link 따라가는 J_U4S_ROD가 있는 쪽). 같은 값에 다시 drive하면 0.2 s, `motion.play REST 0`(→ 13.006)도 빨랐다. MCP 호출이 5분에서 끊겨 그 batch 결과(4번)를 잃었다 — 느린 drive는 따로 보내고 `pending`으로 받은 뒤 측정 batch를 따로 보내야 한다.
- `inspect.clearance` against에 같은 유닛 안의 감속기·볼트(PGX62·CB5-16_M02_*)와 10 mm 매트를 넣으면 맞닿은 쌍과 불리언 실패 쌍 때문에 한 번에 45~65 s, 매트 겹침 자세에서는 수 분이 됐다. 같은 유닛 안 고정 쌍은 빼고 바뀐 상대만 넣으니 17~44 ms.
- batch 안 `inspect.measure`의 인자는 `bodies`(배열)다. `body`를 주면 걸러지지 않고 모든 바디(3,139개)를 재서 106 s·9.6 MB를 돌려준다.
- `edit.checkpoint` id가 뒤 batch들(롤백 포함) 사이에 사라졌다(no checkpoint 3). 포즈만 바꿨으므로 `motion.play REST 0`으로 원복했다.
