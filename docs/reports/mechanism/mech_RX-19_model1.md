## 워크플로우 메모

1. 큰 결과(`inspect.clearance` 여러 자세)는 batch 응답이 그대로 대화에 들어와 맥락을 많이 쓴다. 결과를 파일로 내는 인자가 없다. 자세 묶음을 6개 안팎으로 나누고 `clearance`를 작게 주어 near를 줄였다.
2. `component.delete` 하나가 MCP 응답 시간을 넘기자 MCP 서버가 새 세션으로 다시 붙었다(허용 폴더가 새 임시 폴더로 바뀜, 3D_Modeling 허용도 사라졌다가 저장은 됐다). 앱은 명령을 끝냈다. `running` → `pending`으로 확인하고 이어 썼다.
3. `batch {path}`는 MCP 허용 폴더(임시 폴더)의 파일만 읽는다. 프로젝트 `tools/out/`의 단계 파일을 임시 폴더로 복사해 보냈다.
