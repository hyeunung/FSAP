## 워크플로우 메모

- `component.delete`·`selection.delete {components}`가 큰 설계(피처 3,370)에서 한 번에 약 10분이고, 그 앞 같은 batch의 occurrence.move 결과를 되돌린 일이 있었다(실린더 로드 묶음 이동이 사라져 다시 함). 바디가 남는 컴포넌트를 지울 때는 바디 solid.remove + 빈 컴포넌트 남김이 빠르다. `dry_run`도 실제 지우기·되돌리기라 똑같이 느리다.
- 지운 컴포넌트의 바디를 지운 solid.remove 피처는 그 컴포넌트를 지우면 실패(would_fail)한다 → timeline.edit로 목록에서 빼야 한다(Remove77).
- 같은 이름 스케치가 남아 있으면 `solid.pipe {path_sketch: 이름}`이 옛 스케치를 잡는다. 새 관 스케치는 이름을 바꿔야 한다.
- MCP `batch` 안의 긴 읽기(clearance 10분)는 도구 시간 초과 때 결과를 잃는다. 긴 읽기는 `execute`로 보내 `pending`으로 받는다.
