## 워크플로우 메모

1. MCP 서버 허용 폴더(세 번째): 이 세션에 붙은 서버(PID 42776)는 `--allow-path` 없이 떠 있어 `3D_Modeling/`을 못 열었다. 같은 PC에 `--allow-path …/workspace`로 뜬 서버가 3개 있지만 다른 세션 것이다 → 실행 시작 점검에 'MCP `open`으로 config doc가 실제로 열리나'를 넣고, 안 열리면 모델링 전에 세션을 다시 붙이게 하면 좋다. 이번에도 사용자는 앱에서 과정을 보지 못했다.
2. CLI `run`은 한 단계가 실패하면 `--json-out`을 쓰지 않는다. 볼트 축 위 광선(`view.pick`)이 육각 구멍 바닥 꼭짓점에 맞아 "no outward normal"로 실패해 68단계 확인 한 번(열기 약 190 s)을 버렸다 → 안내서 '볼트 검사'에 '볼트 축 위로 광선을 쏘지 않는다(옆으로 비켜 쏜다)'를 넣고, 실패 전까지의 결과를 남기는 방법이 있으면 적어 두면 좋다.
3. 생성기에서 좌표를 문서 설명 문자열에 손으로 써 두었다가 자리를 바꾼 뒤 설명만 옛 값으로 남아 한 번 다시 저장했다(열기 2번 더) → 설명 · 보고 문자열은 좌표 변수에서 만든다.
4. 지시문 절차 2('먼저 다른 이름 저장 → 그 파일에서 고치고 끝에 save')는 MCP 순서다. CLI 통로일 때는 `--in 앞 버전 --save 새 번호` 한 번이라고 적어 두면 헷갈리지 않는다.
5. 등급: 지시는 S(기존 부품 하나에 살 덧붙임)인데 고침안이 새 구매품 1(볼트) · 둘째 부품(블록 탭)을 넣는다 → regrade M(해석부 보고와 같음).
6. 해석 고침안의 볼트 자리는 손계산(대칭 하중)과 모델 확인(탭 벽 · 머리 틈)이 서로 당긴다. 고침안에 '옮길 수 있는 범위와 그때 달라지는 값'(여기서는 X −280.5 ↔ −280의 벽 · 머리 틈 · 팔)을 같이 적어 주면 모델링부가 다시 셈하지 않는다.
