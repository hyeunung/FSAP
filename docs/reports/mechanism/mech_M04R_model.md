## 워크플로우 메모
- 큰 occurrence 컴포넌트(2,596개)를 `solid.remove` + `component.delete`로 지우면 앱 MCP 한 호출이 25분 걸렸다(8분 상한 넘음). 볼처럼 수천 개짜리는 지울 occurrence만 `selection.delete`하는 쪽이 빠를 수 있다.
- `occurrence.copy`는 새 이름을 '지금 개수 + 1'로 붙여, 중간 occurrence를 지운 컴포넌트에서 복사하면 기존 이름과 겹친다. 생성기는 지운 컴포넌트에서 복사하지 않거나 새 컴포넌트를 쓴다.
- STEP 넣기 바디는 `solid.remove` 뒤 `component.delete`를 하면 Remove 피처가 다시 계산 때 실패한다(앱에서는 바로 안 보이고 저장본 CLI에서 보임). 모델링부의 저장본 CLI 확인이 이것을 잡았다.
- MCP `batch` 결과가 스케치 패턴 id를 모두 돌려줘 응답이 크다(verbose false여도).
