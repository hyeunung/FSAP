- CAD 확인(읽기, CLI `base.sc` = v2.5.7 같은 md5·크기 3,584,127 B): LIFT 0에서 317~323단계 중 **320만** 트레드↔TAPE_G 1.352 mm³(측정과 같은 값). LIFT 1.0으로 둔 318·319·320단계는 **겹침 0**(truncated false). 321(LIFT 30)·322·323은 0.

- 모델링부 몫: X1 키를 넣은 v2.5.8을 **MCP 앱 저장**으로 만들고, 저장 뒤 `bench-open`으로 `adopted`를 확인한다(캐시가 들면 열기 수 초 → 남은 1,655단계가 한 번의 30분 상한 안에 든다).
- 회귀부 몫(묶음 계획 4절): 자세 183점을 같은 수준·X 순서로 다시 줄 세워 쌍 재사용, MAINT_U7는 2단계 묶음 7개, 체결·관은 유닛별 연속 상태. 열기가 그대로(300 s 이상)면 두 회차(각 ≤ 30분)로 나눈다.
- 새 부품 0, 지울 부품 0, 새 구매품 0, 조인트 변화 0. 개념 충돌 없음.
- 미완: 못 본 범위 1,655단계 자체는 다음 회귀 실행이 본다(이 부서는 저장·전체 회귀를 하지 않는다).

## 2. REG-01-X1 — CYCLE_G1 320 먼 쪽 바퀴 ↔ 테이프

### 2-1 현재 키(v2.5.7 `motion.list`, `design/probe_out.json`)
- J_U5_X(48): [0,0],[16,0],[56,1000],[514,1000] → 320에서 바퀴 X ≈ −800(트레드 X −812.5~−787.5).
- J_U5_LIFT(49): [0,30],[56,30],[58,0],[175,0],[176,1],[184,1],[185,0],**[320,0],[321,30]**,[492,30],[493,0],[514,0].
- J_WP_G_ROT: 210→390에서 +90° → −90°(홈 바닥 180° 회전). 320은 회전 중, 다음 단계 321에서 들림. 회전하는 매트의 테이프 띠(Z 10~11)가 들리기 직전 단계에 트레드 −X 가장자리 밑으로 들어온다.

### 2-2 CAD 확인(CLI 읽기, `tools/out/mech_REG-01/design/probe.json` → `probe_out.json`)

| 단계 | J_U5_LIFT | 트레드·바퀴 ↔ TAPE_G·MAT_G·SEAM_G |
|---|---|---|
| 317 | 0 | 0 |
| 318 | 0 | 0 |
| 319 | 0 | 0 |
| **320** | **0** | **1.352 mm³**(bbox X −812.5~−805.4, Y −10.9~−8.3, Z 10.58~11.0, 깊이 0.42) |
| 321 | 30 | 0 |
| 322·323 | 30 | 0 |

### 2-3 고침
- J_U5_LIFT: `[320,0]`을 빼고 `[318,0],[319,1.0],[320,1.0]`을 넣는다 → 185~318 0, 319~320 1.0, 321 30. 바퀴 밑 Z 11 = 테이프 윗면(맞닿음, 부피 0) — 기준선 그대로.
- 1.0 mm 들림은 깊이 0.42의 2.4배. 매트 윗면(Z 10)에서 1.0 뜨는 것은 연구 2단계(319·320)뿐이고 바로 다음 321에 원래도 30으로 든다 — 잡기 손실은 들림을 1단계 앞당긴 정도. 실물에서는 공압 승강이 맞닿음 추종(누름 힘 일정)이라 0.4 mm 차이는 모델 키 표현 문제다(요구서 7절 기록 대상 아님 — 형상 문제 아님).
- 간섭 위험: U5_LIFT 묶음이 0 → 1 → 30으로 단조 상승하고 1~30은 이미 321에서 본 자세 사이이므로 고정 쪽 새 겹침 가능성은 없다. 그래도 회귀에서 CYCLE_G1 317~323을 전 바디로 다시 본다(4절).

- 시험·어림: `--trial-steps 10 --trial-poses 5`, `open_s`는 v2.5.8 `bench-open` 실측값을 넣는다. 시험 경과 − open_s ≤ 0이면 단계당 = 경과 ÷ 시험 단계 수(측정 워크플로우 메모의 함정).

- **A안(캐시 듦):** 한 회차, 전체 상한 1,800 s.
- **B안(캐시 안 듦):** 회차 1 = 연구(G1 다시 + L + S + G2, 80단계 묶음 20개), 회차 2 = POSE·MAINT_U7·F_STATES. 각 회차 상한 1,800 s, 병렬 6 → 회차당 약 3.5물결 × 8분. 두 회차가 다 끝나야 REG-01 해결.
- 판정: 새 겹침 0(기준선·나사 물림 unchecked 제외), truncated 0, 호출 ≤ 480 s, 본/못 본 범위 표.

2. `edit.checkpoint`. `motion.list`로 CYCLE_G1 키를 읽는다(지금 값은 `tools/out/mech_REG-01/design/probe_out.json` [0] studies CYCLE_G1, 조인트 id 17개). 회전 조인트(47·50·84·99·114·270)는 라디안 → 도로 바꾼다(WF-117).
3. J_U5_LIFT(49)만 2-3대로 바꾸고 나머지 16 조인트 키는 그대로 `motion.study {study:"CYCLE_G1", steps:514, keys:[…17개 전부]}`(키 하나만 주면 나머지가 지워짐 — gen_v2_m06 실측). 생성기 `tools/gen_v2_reg01.py`로 남긴다.
4. 확인(앱, 짧은 것): CYCLE_G1 319·320 `motion.play` → `inspect.clearance {bodies:[P_M03_WHEEL_TREAD,P_M03_WHEEL], against:[TAPE_G,MAT_G,SEAM_G]}` 겹침 0. `motion.list`로 LIFT 키가 12 → 13점인지.

## 워크플로우 메모
- CLI `--save`로 저장한 파일은 `saved_model: false`라 열 때마다 피처 전부를 다시 계산한다(v2.5.7 254 s). 모델링 저장을 앱으로 하고 저장 확인에 `bench-open`의 `adopted`를 넣으면 회귀 시간이 크게 준다.
