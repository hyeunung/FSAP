## 워크플로우 메모

1. **`sketch.move_point`는 구속이 덜 된 스케치(dof 5)에서 다른 점을 1e-3쯤 흐트러뜨린다.** p2 · p3를 옮겼더니 p1이 (−5.5, −168.5) → (−5.4984, −168.4989), 호 반지름 2.5 → 2.5008이 됐다(오류 · 경고 없음, 부피로도 0.04 mm³ 차이라 잘 안 보임). 스케치 · 컷을 지우고 `timeline.add`로 정확한 좌표를 다시 넣어 풀었다. 안내서에 "점을 옮긴 뒤 `sketch.inspect`로 모든 점 좌표를 확인, 구속이 덜 된 스케치는 지우고 다시 넣기"를 적으면 좋겠다.
2. **앱을 오래 켜 두면 느려진다.** 전날 16:21에 켠 앱이 메모리 40.4 GB였고, 앞 회차(같은 날 10:40쯤) 64~145 s이던 `timeline.roll_to end`가 약 27분, `inspect.clearance` 0.36 s → 19~30 s, `joint.drive` 0.5 s → 12~21 s, `save` 64 s → 116 s로 늘었다. 과제 사이(저장 직후)에 앱을 다시 켜는 단계가 있으면 좋겠다(undo 200단계 · 체크포인트가 쌓이는 듯 — 확인 못 함).
3. 다른 연결의 긴 요청이 도는 동안 새 MCP 연결은 첫 `mcp.options`부터 줄을 선다. 그래서 새 연결로는 `running`도 답을 못 받는다(이미 붙어 있던 연결의 `running`만 바로 답함). 기다리는 스크립트를 새 연결로 짜면 안 된다.
