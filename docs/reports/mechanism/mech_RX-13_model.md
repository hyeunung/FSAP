## 워크플로우 메모

1. **옛 볼트 occurrence 6개 `selection.delete` 한 번이 72분 걸렸다**(1 코어 꽉, 앱 메모리 61 GB). 지시문 (i)의 "마커를 내리고 지우기를 몰아 한 뒤 한 번만 올린다"를 occurrence 지우기에도 적용했어야 한다 — RX-14는 마커를 내리고 487피처를 2.2 s에 지운 뒤 한 번 다시 계산(약 10분)했다. 안내서에 "앞쪽에서 넣은 occurrence · 컴포넌트를 지울 때는 마커를 그 앞으로 내리고 지운다"를 넣으면 좋겠다. 기다리는 동안 앱은 다른 요청을 못 받았다(`running`은 답함).
2. 서버 도구 `batch` · `joint.*` 응답에 모든 occurrence의 dof(2,964줄)가 붙어 `verbose: false`여도 62만 자다. 브리지 스크립트로 파일에 받고 요약만 봤다. `quiet` 같은 인자를 `batch`에도 주면 좋겠다.
3. 설계안의 관 좌표가 옛 길(M02R)이었다. 설계부가 "지금 경로 그대로"를 쓸 때는 지금 스케치(`sketch.inspect`)에서 읽게 하면 좋겠다. 형번 `HNTT8-5`도 `stepcheck`는 '있음'이지만 다른 부품이었다 — 형번을 고를 때 STEP 크기를 한 번 재면 걸러진다.
4. `ledger.py sigpatch --removed`는 서명 경로 키인데 `boltpatch`는 같은 값을 체결 이름으로 쓴다. 지운 볼트가 `bolts.json`에 남는다.
5. 이 세션의 MCP 서버 허용 폴더는 `3D_Modeling`뿐이었다(지시문은 workspace 전체). 내보내기는 브리지(`--allow-path workspace`)로 했다.
6. `save {path}`가 응답 시간 초과로 돌아왔지만 저장은 됐다. `running` 빈 목록 + 파일 시각 + dirty로 확인.
