## 3. 동작 문제

### P1 — 관 RX08_A가 로드 쪽 피팅을 뚫음

- 증거(`view.pick`, J_U4_X 0 · REST):
  - 관 A 윗면 Z 194.5가 X −366 · −361 · −342 · −325, Y 47.2에서 이어진다. 옆면 Y 50.2는 X −366 · −342에 있다.
  - X −351.5에서 +Y 쪽 광선은 관(Y 50.2)보다 먼저 피팅 면 Y 50.7에 닿는다. 관이 피팅 몸 안에 있다는 뜻이다.
  - 관 축(Y 47.2, Z 191.5)을 따라 X −340 → −X로 쏜 광선은 X −348에서 피팅 면에 닿는다.
  - 피팅 bbox는 X −356.7~−346.3, Z 175~196.7이다. 그 X 폭 약 10.4 동안 관 단면 Ø6 전체가 피팅 몸 안을 지난다(어림 200~290 mm³).
  - `inspect.clearance`와 `inspect.interference` 모두 이 쌍을 unchecked로 냈다. SMLib 허용차 실패, 관 쪽 첫 피연산자 문제다.
- 고치는 방법(치수):
  - HEAD 피팅 `KQ2L06-M5A_RX08_HEAD`를 축 (−384.5, 47.2)에서 Z축으로 90° 돌린다. 출구는 +X에서 +Y로 바뀐다.
  - 관 A를 출구 → Y 62(R10 굽힘) → Z 191.5에서 +X로 X −310까지 → 올림으로 다시 쓴다.
  - 블록 관 구멍을 (−310, 47.2)에서 (−310, 62)로 옮긴다. 관 B 구멍 (−295, 61)과 중심 거리는 15.0이다.
  - Y 62 줄은 ROD 피팅 +Y 끝 51.24와 3.76 떨어진다(관 반지름 3 뺀 값). 스토퍼 몸 Z ≤ 178과 플로팅 조인트 Z ≤ 170보다 위다.
  - 고친 뒤 관 ↔ 피팅은 불리언이 실패하므로 `inspect.clearance`가 아니라 광선이나 간격 측정으로 본다.

## 워크플로우 메모

- 15자세 93단계를 batch 하나로 보냈더니 MCP 요청 시간이 넘었다. Claude 쪽 MCP 서버가 다시 떴고(허용 폴더 `solidcraft-mcp-<pid>`가 바뀜), 결과는 받지 못했다(앱은 끝까지 돌았고 running은 비어 있었다). 3자세(18단계, 약 7 s)씩 나누니 문제가 없었다.
- MCP 서버의 batch `path`는 허용 폴더(Temp/solidcraft-mcp-*) 밖을 거부한다. 스크립트를 그 폴더에 복사해 썼다.
- `inspect.measure {body}`를 batch 단계로 쓰면 body가 무시되어 전체를 잰다(18.5 s, 4 MB). `measure` 도구 이름 단계로 부르면 한 바디만 잰다.

- 이웃 유닛 조인트는 그 유닛이 쉬는 자리만 보면 안 된다. 허용 제어 제약의 한계 자세(이번 d₂ = d₁ + 240)를 넣어야 한다(이번 P2).
