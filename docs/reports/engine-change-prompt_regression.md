## 0. 관찰된 사실(실측)

| 항목 | 값 |
|---|---|
| 설계 파일 | 약 12 MB 이상, 바디 수백 개, 조인트 10개, 동작 연구 10개 |
| 전체 회귀 지시 | modeling_round.js `MOTION` "0-3 사이클 전 단계(6-4 상태 목록, 행정은 5 mm 간격)" |
| 실제로 만든 검사 | 모든 연구 + 모든 조인트 전 행정을 5 mm 간격으로 보충 → 약 47,000단계, 5묶음 병렬 |
| 묶음 호출 하나 | 95분(안내서 '호출마다 8분 안'을 넘김, 막는 장치 없음) |
| 실패 | CAD 커널 패닉(`tolerance must be no less than 1e-6`)이 err 파일에 쌓였는데 95분 뒤 묶음이 끝날 때까지 기다림 → 5묶음 모두 실패 |
| 다시 실행 | 범위를 줄인 판 31~55분 |
| 합계 | 3시간 넘게 끝나지 않아 사용자가 멈춤. 그동안 라운드 전체가 멈춰 있었다 |

원인은 CAD 속도가 아니라 절차다: ① 간격이 행정 길이와 상관없이 고정, ② 시험 실행 없음, ③ 호출 시간 상한을 부서 지시로만 둠, ④ 오류를 끝날 때까지 안 봄, ⑤ 전체 상한·넘을 때 처리 없음.

## 1. 검사 간격을 요구서가 정하게

- `MOTION`의 "행정은 5 mm 간격"을 고정값으로 두지 않는다. 요구서 6-4(동작 검사 범위)에 **간격 칸**을 둔다: 긴 이송 행정 간격, 회전 간격, 좁은 곳(작업 도구 둘레 반경 r 안·좁은 홈·모서리 회전 구간) 간격, 짧은 행정 조인트는 양 끝 + 가운데.
- 6-4에 간격이 없으면 기본값: 행정 길이 / 40(최소 5 mm, 최대 25 mm), 회전 5°, 좁은 곳 5 mm·1°.
- 템플릿 `design-requirements-template.md` 6-4 설명에 간격 칸을 더한다.

## 2. 전체 회귀 실행 절차(워크플로우가 강제)

1. **단계 수 어림:** 묶음을 만들기 전에 총 단계 수 × 단계당 시간(시험값)으로 전체 시간을 어림해 결과 `timing`에 남긴다.
2. **시험 실행:** 묶음 하나의 앞 20단계를 먼저 돌린다(2분 안). 오류·패닉이 있거나 어림이 상한을 넘으면 범위를 줄이고 이유를 보고서에 적는다.
3. **호출 상한:** CLI 호출 하나 8분. 워크플로우(또는 부서 실행 스크립트)가 경과를 재서 넘으면 끊고 그 묶음을 반으로 나눠 다시 낸다. 부서 지시로만 두지 않는다.
4. **오류 즉시 확인:** 묶음 err 출력에 패닉·예외가 나오면 그 묶음을 바로 멈추고, 실패한 단계를 찾아 빼고 나머지를 돌린다. 뺀 단계는 보고서에 '못 본 범위'로.
5. **전체 상한:** 기본 30분(요구서 6-4 또는 실행 인자로 바꿀 수 있음). 넘으면 거기서 끊고 '본 범위 / 못 본 범위'를 보고서 맨 위에 적고 라운드를 넘긴다. 못 본 범위는 다음 라운드 전체 회귀가 먼저 본다.
6. **기다리는 법:** 묶음 끝을 수 분짜리 sleep 반복으로 기다리지 않는다. 짧은 간격으로 진행 파일·err를 확인한다(오류를 바로 보기 위해).

## 3. 시간 기록·위반

- 전체 회귀 `timing`에 어림 시간, 실제 시간, 묶음별 시간, 끊은 호출 수, 뺀 단계 수를 적는다.
- 상한을 넘긴 실행은 `violations`에 올리고 회고가 원인을 본다.

## 4. 구동 개념은 벤치마크를 거의 그대로(E-01 보탬)

- 사용자 원칙: 벤치마크(경쟁 기계·만료 특허)가 있으면 **거의 그대로 만드는 방향**이 가장 쉽다. 새로 고안하는 것은 벤치마크로 안 되는 곳만.
- 시작 세션이 0-8을 세울 때: 유닛마다 "그대로 가져오는 벤치마크(출처)"와 "새로 하는 것"을 나눠 적는다(템플릿 0-8-3 유닛 표에 두 칸 추가). 새로 하는 것은 이유(벤치마크로 안 되는 근거)를 적는다.
- 벤치마크 조사가 얕으면(구조·이송 주체·잡기·센서·모서리 처리 중 비어 있는 것이 있으면) 0-8을 세우기 전에 조사를 먼저 한다.
- 구상 단계(과제 안)도 같은 원칙: 첫 안은 벤치마크 그대로, 다른 안은 그것이 안 될 때만.

## 5. 마무리

- 버전을 올리고 CHANGELOG에 WF 번호로 적는다. 시험(test_fake_agents.js)에 ① 6-4 간격이 지시문에 들어가는지 ② 호출 상한·전체 상한·시험 실행 문구가 전체 회귀 지시문에 있는지 ③ 0-8 유닛 표 벤치마크 칸 검사를 더한다.
- 우선순위: 2(실행 절차 강제) → 1(간격) → 3(기록) → 4(벤치마크 우선).
