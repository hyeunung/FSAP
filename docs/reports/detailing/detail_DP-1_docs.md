## 2. BOM을 고친 방법

스크립트 하나로 다시 만들 수 있게 했다: `tools/out/detail/DP-1_v2306/mkbom.py`(입력은 같은 폴더의 `made_before.csv` · `purchased_before.csv` — DP-1 전 BOM 사본, 결과 `bom_result.json`).

- 입력 자료: 구매원가부 `tools/out/detail/procure/purchased_judged.json`(133형번의 BOM 행 · 모델 수) · `made_judged.json`(198품번), 판금 · 가공부 `tools/out/detail/sheet_v2306/sameshape.json`(같은 형상 묶음).
- 구매 BOM: 형번마다 흩어진 행을 하나로 합쳤다. 수량은 모델 수, '모델 바디' · 비고 · 자료대기는 합친 행의 것을 " / "로 이었다(과제별 이력 보존). 관 2형번(TU0805 · TU0604)은 길이로 사므로 줄 수만 모델 바디 수로 적고 길이 표기는 그대로 두었다. 케이블 타이 · 인장 스프링(모델 없음)은 BOM 값 그대로.
- 가공 BOM: 모델 품번 198개를 기준으로 행을 다시 세웠다. 같은 형상 묶음(거울 짝 1묶음 제외 30묶음)은 대표 바디 이름을 품번으로 하고 묶인 바디와 개수를 '모델 바디' 칸에 적었다. 질량 칸이 '미확인'이던 행은 서명 표의 모델 질량으로 채웠다(측정값).
- 따옴표 없는 쉼표로 칸이 넘쳐 있던 옛 행(구매 3 · 가공 1)은 비고로 되돌렸다.

## 4. 미완 · 넘긴 것

- 회귀 D1은 문서 제약으로만 닫혔다. 실행 지시 (라)는 기구로 막는 안을 요구했으나 PM이 재서 디테일 범위 밖(구동 과제 후보 D1-STOP)으로 판정했다 — 최종 보고에 구동 후보 1건으로 올라가야 한다.
- 정비 순서 가운데 `CB5-16_M04K_NY`(:62, 가스 스프링 쪽 0.4 mm 모자람)는 먼저 뗄 부품을 정하지 못했다(보고서에 근거가 없다) — 기록.
- 가격 칸: 가공 145행 전부 · 구매 129행 미확인.
- SSE2B13-220의 한국 미스미 표기 · 판매 상태는 확인하지 않았다(브라우저 미사용).
- DP-2~DP-6이 볼트 형번 · 수량을 바꾸면 그 묶음의 문서 담당이 이 BOM을 새 번호로 복사해 고친다(예: CB4-12 31 → 12, CB4-20 21 → 3은 DP-4 · DP-5 뒤).

## 워크플로우 메모

1. 문서만 묶음의 커밋: 지시문은 "커밋한다 … 방식은 요구서 8-5"인데 8-5는 버전이 안 바뀐 문서를 다음 버전 커밋으로 미룬다. 문서만 묶음이 앞에 오면 그 문서가 다음 묶음 담당의 "이번에 쓴 파일만 add"에서 빠질 수 있다 — 다음 묶음 지시문에 '앞 문서만 묶음의 파일 목록'을 넘겨야 한다.
2. matcheck는 BOM 품번 칸만 본다. M-12대로 같은 형상을 한 품번으로 합치면 묶인 바디 53개가 "BOM에 없는 부품"으로 나온다(재질 불일치 수에는 `P_M07_SEAT_PX` 1건이 '새 부품 · 기본 재질'로 섞인다). 합친 BOM을 읽을 칸(모델 바디)이 도구에 없다.
3. `tools/out/detail/DP-1/`에는 2026-10-31(v0.x) 디테일링의 같은 이름 묶음 원본이 남아 있었다. 이번 것은 `DP-1_v2306/`에 따로 두었다. 결정로그에도 같은 제목 절(2026-10-31)이 있어 날짜로만 구분된다.
4. 구매 BOM에 따옴표 없는 쉼표로 칸이 넘친 행이 4개 있었다(CSV를 손으로 이어 쓴 흔적). 형번당 1행 · 스크립트 생성으로 바꾸면서 없어졌다.
