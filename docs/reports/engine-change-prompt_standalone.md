엔진 작업이다. MechDesign_Engine(v3.2.1)을 고친다. 아래 내용은 실제 프로젝트 실행(자동 봉제기 기구 개발)에서 나온 문제다. 프로젝트 파일은 이 PC에 없으니 찾지 말고, 아래 내용만으로 엔진을 고친다.

## 1. 완료될 때까지 스스로 이어 돌기 (roadmap R3·R2·R1)

배경: modeling_round(mechanism)가 끝나면 실행이 멈췄다. roadmap R3에 "R3 보류: 구동부 워크플로우가 끝나면 멈추고, 사용자가 '디테일링 시작해'라고 하면 시작"이라고 되어 있기 때문이다. 요구서 과제는 전부 '해결'이었지만 디테일 30건 이상, 구동 후보 여러 건, STEP대기_ 10개가 남아 제품으로 낼 상태가 아니었다. 사용자: "구동부 끝이라는게 완전히 완료되는거 말하는거야 제품으로 나가도되겠다 이프로젝트의 구동부가 100%끝났다".

- R3: 보류를 푼다. "모델링 해줘"를 받으면 구동부를 먼저 100% 끝낸다.
  - modeling_round(mechanism)를 구동 과제·구동 후보가 0이 될 때까지 거듭 부른다.
  - 그다음에 detailing_round를 한 번 부른다.
  - 구동 ↔ 디테일링을 번갈아 돌지 않는다. 사용자: "구동부 하나 하고 디테일링하고 또 구동부 하나 하고 디테일링하고 이것도 하지 말라고 했잖아. 구동부 다 완료가 되고 나면 디테일링을 하라니까".
  - 합친 스크립트든 세션 절차든 된다. 라운드마다 사용량은 보고하되 멈추지 않는다.
- mechanism 라운드의 측정·검증이 디테일링에서나 드러나던 구동 후보를 미리 찾게 한다.
  - 배치 때문에 막히는 볼트 렌치 접근
  - 구매품 수량·외형이 BOM과 맞는지(예: 레일마다 블록 2개인 BOM인데 모델엔 1개)
  - 높이 사슬(레일·블록·받침·판 두께 누적)
  - 이번 실행에서 디테일링이 구동 후보 7건을 냈다: X 받침 볼트 렌치 접근 불가, 레일 블록 수, 레일 높이 사슬, 칼 팔 축 위치, 패드 위치, 옆·뒤 커버, 공압 포트 방향. 구동 단계가 놓친 것이다.
- R2 완료(출시 가능) 조건: 아래가 모두 0.
  1. 요구서 5절 열린 구동 과제
  2. 디테일링이 낸 구동 후보(motion_task_candidate)
  3. 마지막 전체 회귀의 동작 문제
  4. 디테일(SF·체결·빈 구멍·판금)
  5. 형번이 정해졌는데 STEP대기_로 남은 구매품
  - 사용자 자료로만 풀리는 것(기종 미정, 납품처 안전 기준, 사이트 로그인)만 남으면 '사용자 자료 대기'로 멈추고 그 목록을 최종 보고 맨 위에 적는다. '완료'라고 쓰지 않는다.
- R1: tasks를 args JSON으로 손으로 쓰지 않는다. 요구서 5절 과제 목록, 디테일링 구동 후보, 모델의 STEP대기_ 목록을 워크플로우가 직접 읽어 다음 라운드 과제를 만든다.
- E-02 순서(구동 → 브래킷 → 디테일)는 그대로 둔다.

## 2. 프로젝트 규칙 파일 인자 rulesFile

배경: 프로젝트 고정 규칙(엔진 읽기만, MCP/CLI 나눔, 새 번호 저장, Git, 구매 사이트 규칙, 로그인 확인, 완료 기준 등 13개, 약 5천 자)을 매 실행 shellNote에 통째로 복사했다.

- modeling_round·detailing_round 둘 다 인자 rulesFile(예: <root>/tools/run-rules.md)을 받아 그 내용을 모든 부서 지시문 머리에 붙인다.
- shellNote는 실행마다 바뀌는 것(과제, 그 실행만의 기본값)만 받는다. 둘 다 주면 둘 다 붙인다.
- rulesFile을 줬는데 파일이 없으면 시작하지 않고 알린다.
- templates/project-layout.md 인자 표에 추가하고, 프로젝트 템플릿에 tools/run-rules.md 자리를 둔다.
