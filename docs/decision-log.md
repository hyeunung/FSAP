# MAT-RS-001 결정로그

- 기계 결정과 이유를 남긴다. 한 줄 = 결정 하나. 형식: `id | 결정 | 이유 | 근거`.
- 대화 단계 결정은 C-번호, 워크플로우 라운드 결정은 그 라운드 절에 이어 쓴다(엔진 형식).
- 엔진·워크플로우 자체의 문제는 여기 쓰지 않는다(보고서 `## 워크플로우 메모` → 엔진 개선후보).

## 대화 단계 (2026-10-30)

| id | 결정 | 이유 | 근거 |
|---|---|---|---|
| C-01 | **R375X를 벤치마크로 삼고 그 구조를 기본으로 한다.** 헤드 고정, 매트가 헤드 밑을 지나며 회전·이동, 형상 자동 인식(차종별 프로그램 없음), 테이프 자동 공급·커팅, 수동 로딩 뒤 자동 사이클 | 만들려는 기계가 바로 이것이다. 방식 비교를 처음부터 다시 하지 않는다 | 사용자 "우리가 만들고자 하는게 저거야", "딱 이거를 벤치마킹 하면 될거같다니까". [benchmark.md](benchmark.md) |
| C-02 | **형상은 카메라로 전체를 찍지 않고, 바늘 앞 가장자리 센서로 봉제 중에 따라간다.** 차종별 형상 등록(사진·재단 DXF)은 보조 후보로만 둔다 | R375 계열 "edge reading" 표현, 비슷한 기계(Richpeace)와 만료 특허(US6557478 기계식 감지 암, US5367966 광센서)가 모두 이 방식이다 | 사용자 "카메라로 메트를 찍을거같진 않아 그냥 센서가 메트 외곽을 감지한테로 돌거같은데" |
| C-03 | **매트는 넓은 면으로 잡는다(진공 원판·판 클램프 우선 후보). 롤러로 파일 면을 세게·좁게·반복해서 누르지 않는다** | 전임 의뢰 기계가 롤러로 매트를 눌러 눌림자국이 났고 퇴짜 사유가 됐다. US6557478(진공 원판), US5367966(두 판 클램프)은 롤러 없이 잡는다 | 사용자 "매트를 잡고 있는 롤러가 메트를 눌러서 눌림 자국이 난게 퇴짜맞은 이유중 하나" |
| C-04 | **최우선 요구: 좁은 홈·오목 모서리까지 깔끔한 마감, 영구 눌림자국 없음**(요구서 1-1) | 대기업 납품 제품. 전임 기계는 마감 품질도 나빴다. R375X가 좁은 홈을 처리하는지는 공개 자료로 알 수 없어 여기가 차별점이다 | 사용자 "좁은곳도 마감에 문제 없이 깔끔하게 잘 나와야한다", "마감품질도 좋지도 못 했고" |
| C-05 | **작업자는 매트만 올린다. 그 뒤는 사람 손 없이 자동.** 힐패드·고정 단추는 범위 밖 | 사용자 목표 운전 방식 | 사용자 "사람손 안거치고 매트만 넣어주면 자동으로 되도록" |
| C-06 | **만료 특허의 아이디어는 그대로 쓴다.** 침해 여부 조사(FTO)는 하지 않았다 | 찾은 특허(US6557478, US5367966, US5216969, US5209171, CN207958657U, CN215051175U, WO1996023626)는 모두 만료·소멸 표시. 벤치마킹이다 | 사용자 "벤치마킹하는거니까 상관없을거같은데 그리고 만료라며" |
| C-07 | **저장소를 기구 개발 폴더로 바꾼다.** 6단계 폴더(01_Planning~06_Business)를 지우고 엔진 기본 배치로. 결정은 ADR 대신 이 결정로그에 쓴다. ADR-004는 대체됨, ADR-001~003은 유효 | 6단계 폴더·AI 부서 규칙은 FSAP에서 AI 부서를 만들려다 멈춘 흔적이다. 기구 모델링 엔진은 MechDesign_Engine으로 따로 만들었다 | 사용자 "여기는 저 기구 개발하는 폴더로 바꿨으면 좋겠어", "일단 기구개발 폴더로 변경해줘봐" |
| C-08 | 차종마다 매트 형상이 다르다. 한 형상에 맞춘 고정 지그·고정 경로는 쓰지 않는다 | 형상 자동 인식(C-02)이 필요한 이유 | 사용자 "차종마다 형상이 다 달라" |
